

## Production schema extension

The existing `users`, `news_events`, `push_tokens`, and `source_records` tables remain the foundation. The following relational model is the target contract for production persistence; JSON payload columns preserve provider-specific detail while normalized columns support filtering, sorting, and joins.

| Table | Key fields and data types | Relationships and purpose |
|---|---|---|
| `users` | `id INT PK`, `openId VARCHAR(64) UNIQUE`, `name TEXT`, `email VARCHAR(320)`, `role ENUM`, `createdAt TIMESTAMP`, `updatedAt TIMESTAMP`, `lastSignedIn TIMESTAMP` | Auth identity and admin authorization |
| `user_preferences` | `id BIGINT PK`, `userId INT FK`, `themeId VARCHAR(32)`, `themeMode ENUM`, `customPalette JSON`, `assistantMode ENUM`, `retentionDays INT`, `createdAt TIMESTAMP`, `updatedAt TIMESTAMP` | Account-scoped UI and Assistant preferences |
| `watchlists` | `id BIGINT PK`, `userId INT FK`, `name VARCHAR(128)`, `createdAt TIMESTAMP`, `updatedAt TIMESTAMP` | User watchlist containers |
| `watchlist_items` | `id BIGINT PK`, `watchlistId BIGINT FK`, `symbol VARCHAR(32)`, `exchange VARCHAR(32)`, `displayName VARCHAR(255)`, `addedAt TIMESTAMP` | Symbols in a watchlist; unique by watchlist and symbol |
| `saved_screens` | `id BIGINT PK`, `userId INT FK`, `name VARCHAR(128)`, `filters JSON`, `strategyId VARCHAR(64)`, `createdAt TIMESTAMP`, `updatedAt TIMESTAMP` | Reusable screener configurations |
| `recent_searches` | `id BIGINT PK`, `userId INT NULL FK`, `symbol VARCHAR(32)`, `displayName VARCHAR(255)`, `assetType VARCHAR(32)`, `searchedAt TIMESTAMP` | Local or synced recent search history |
| `provider_registry` | `id BIGINT PK`, `providerKey VARCHAR(64) UNIQUE`, `name VARCHAR(128)`, `capabilities JSON`, `enabled BOOLEAN`, `requiresCredentials BOOLEAN`, `licenseNotes TEXT`, `createdAt TIMESTAMP`, `updatedAt TIMESTAMP` | Canonical provider catalog |

## Relationship rules and indexes

`users` own preferences, watchlists, saved screens, conversations, alerts, and optional research reports. `source_records` are referenced by news, flow, options, fundamental, and report evidence. `provider_registry` has one-to-many health records and source records. `strategy_definitions` own strategy runs, and runs own candidates. Conversations own ordered messages. Recommended indexes are `(symbol, publishedAt)`, `(symbol, reportDate, participant)`, `(sector, reportDate)`, `(providerId, status, cooldownUntil)`, `(userId, searchedAt)`, and `(conversationId, createdAt)`.

Raw provider payloads are immutable and access-controlled. Normalized JSON is versioned by parser version. Deleting a user removes or anonymizes user-owned rows according to retention policy while preserving legally required operational and provenance records without personal identifiers.

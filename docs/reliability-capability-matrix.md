# AnalyzerX Capability Contract

This document is the release gate for user-facing AnalyzerX functionality. A capability may be shown as available only when its declared prerequisite, success path, fallback behavior, and validation gate are met. No capability should remain indefinitely loading or fail without a user-safe explanation.

| Area | Primary capability | Runtime class | Required prerequisites | Success state | Safe fallback | Validation gate |
|---|---|---|---|---|---|---|
| Live and news | Read live market context and verified news | Managed service required | Reachable API; at least one valid public/provider source | Fresh timestamped records and provenance | Last verified cache with age; unavailable-source notice | News, provider, and cache tests |
| News archive | Filter, read, export, and inspect source freshness | Managed service required with local export history | Reachable archive API or cached prior result | Filtered archive and source provenance | Persisted archive/cache or an explicit no-coverage state | Archive and export tests |
| Company analysis | Produce source-backed company analysis | Managed service required | Valid symbol; API; analysis lanes | Completed or partial result with lane status | Completed lanes plus retryable unavailable-lane state | Analysis-route and partial-result tests |
| Flows | Display institutional and market flow data | Managed service required | Valid market source and API | Timestamped flow cards/tables | Latest verified snapshot with age or source-unavailable state | Flow data and provider-state tests |
| Screener, sectors, graph | Browse market analytics and navigation | Managed service required | API and selected market/symbol when required | Query result with source timestamp | Cache/empty explanation; no dead navigation | Route, navigation, and data tests |
| Filings and disclosures | Read official filings and comparisons | Managed service required | API and official-source collector availability | Source-linked filing result/export | Explicit source-unavailable or no-record state | Filing parser and export tests |
| Research desk and workspace | Run evidence-driven research and save local workspace state | Managed service required plus device cache | API; valid query; configured research lanes | Completed/partial research result with limitations | Local saved workspace and per-lane failure details | Research-desk, evidence, and history tests |
| Market chat and assistant | Ask source-aware market questions | Managed service required | API; available cloud LLM or deterministic fallback | Structured answer with evidence/limitations | Non-LLM source-backed result or typed model error | Market-chat runtime and LLM health tests |
| Reports and exports | Generate PDF/CSV/markdown artifacts | Managed service required plus device storage | API; data result; share/export permission where needed | Download/share artifact with metadata | Clear generation or device-storage failure | Report and export tests |
| Alerts and notifications | Create and manage market/research alerts | Managed service required plus device permission | API; account where needed; notification permission | Persisted alert and delivery status | Permission/setup explanation; no false scheduled state | Alert and preference tests |
| Data truth and provider admin | View readiness, evidence, provider health, and collector state | Optional admin capability | API; administrator session for protected actions | Observed health/telemetry with timestamps | Public read-only state or access-required state | Admin authorization and provider-health tests |

| Local AI telemetry | Inspect/export local model runtime telemetry | Device-only after Local AI execution | Local telemetry records; device storage | Local history/export | Empty telemetry state | Telemetry and export tests |

## Shared Operation States

Every long-running action must publish one of the following states to the UI and diagnostics: `preflight`, `fetching_market_data`, `collecting_news`, `collecting_flows`, `retrieving_filings`, `reasoning`, `assembling_report`, `downloading_model`, `verifying_model`, `loading_runtime`, `partial_result`, `completed`, `retryable_failure`, or `blocked`.

The required UI content is the action name, current stage, elapsed time, fresh/cache context where relevant, a user-safe reason when blocked or failed, and a retry/cancel action only when it is valid. Full implementation references are maintained in the matching automated test files and the release verification report.
